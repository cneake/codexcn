## 二、数据安全 — 应用级透明加密

### 背景

当前状态：SQLite 数据库明文存储，文件被拷贝即可读取所有 API Key。

涉及敏感数据：
- providers 表的 api_key、token、secret
- mcp_servers 表的 api_key
- sessions 表的 token

### 设计原则

- 密钥永不落磁盘（内存管理，关程序丢失）
- 只加密值，不加密结构（调试友好）
- 向后兼容已有用户（无密码直接进）
- 用户可选开启（不影响现有用户体验）

### 加密方案

**算法：Argon2id + AES-256-GCM**

- Master Password：CodexHub 自动生成，用户一次性保存
- Master Key：程序级 256-bit 密钥，内存中使用
- 存储：password hash + salt + encrypted_master_key 到 DB 固定位置

### 首次启动流程

```
CodexHub 首次启动
  → 全屏引导页
  → 自动生成 32 位 Base64 随机密码
  → 展示密码（大字醒目）
  → 提供"一键复制" + "下载 txt 文件"两个保存方式
  → 用户确认"我已保存" → 进入主界面
  → 密码 hash + salt + encrypted_master_key 存入 DB
```

### 后续启动流程

```
启动 → 加载遮罩 + 底部嵌密码输入框
  → 用户输入密码
  → 验证成功 → 进入主界面
  → 验证失败 → 提示重试（3次后需重启）
  → 忘记密码 → Reset 选项（知情同意，数据清空）
```

### 内置网站导流入口

启动流程底部小字：`还没有网站账号？注册，享受云端同步和 Token 购买服务`
（非强制，不打断主流程）

### 技术依赖

```toml
aes-gcm = "0.10"
argon2 = "0.5"
rand = "0.8"
```

## 三、侧边栏第二栏 — 工具菜单聚合

### 目标

聚合每个工具的原生菜单到 CodexHub，用户无需记忆命令，直接点菜单执行。

### 布局设计

```
┌──────────────────────────────────────────────────────────┐
│  52px   │   220px (第二栏)    │     主内容区 (flex)     │
│ 图标轨   │  工具功能菜单         │                        │
│          │                      │                        │
│ Claude   │  ▸ --help            │                        │
│ Codex    │  ▸ --verbose         │                        │
│ Gemini   │  ▸ --no-input        │                        │
│ OpenCode │  ▸ --model <model>   │                        │
│ OpenClaw │  ▸ MCP:start        │                        │
│ Hermes   │  ▸ Config            │                        │
│ DeepSeek │                      │                        │
└──────────────────────────────────────────────────────────┘
```

### 第一栏：一键功能（已有）

- 启动 / 停止
- 检查更新
- 打开配置目录
- 诊断冲突

### 第二栏：原生菜单（新增）

#### 数据来源：方案 A（PTY 交互模式） + 降级方案 B（--help 静态解析）

```
尝试 PTY 交互模式
  ↓ 失败/超时（3s）
降级到 --help 静态解析
  ↓ 失败/超时（3s）
显示"该工具暂不支持" + 手动输入框
```

#### 获取流程

```
用户选中某工具（如 Claude Code）
  ↓
检查本地缓存 ~/.codexhub/menus/{tool}.json 是否过期（7天）
  ↓
未过期 → 直接渲染
过期/无 → 调用 PTY 交互模式 / --help
  ↓
解析 stdout → 转为 MenuItem[]
  ↓
存入缓存文件
  ↓
渲染到第二栏
```

#### 菜单项数据结构

```json
{
  "tool": "claude-code",
  "version": "2.1.138",
  "fetched_at": "2026-06-29T14:00:00Z",
  "items": [
    {
      "command": "claude",
      "description": "Start a new conversation with Claude"
    },
    {
      "command": "claude --verbose",
      "description": "Enable verbose output"
    }
  ]
}
```

#### 点击执行

用户点击菜单项 → 在该工具的 Terminal 中执行命令 → 保留 Terminal 窗口让用户看到输出

## 五、待确认事项（已解决）

| 问题 | 结论 |
|------|------|
| 密码生成方式 | CodexHub 自动生成 32 位 Base64，用户只管保存 |
| 密码保存方式 | 一键复制 + 下载 txt 文件，两者都要 |
| 密码遗忘处理 | Reset 选项，知情同意，数据清空 |
| 弹窗体验 | 密码框融入启动遮罩，不单独弹窗 |
| 网站导流 | 内置小字链接，非强制 |
| 菜单方案 | 优先 A 方案，降级 B 方案 |
| 菜单执行后 Terminal | 保留窗口，用户可看到输出 |
| 版本节奏 | v0.1.0 稳定后再做 v0.1.1 |

## 六、风险与注意事项

1. **加密不可逆**：密码丢失 = 数据清空，Reset 流程必须有明确的用户确认
2. **PTY 兼容性**：Claude Code 交互模式可能在非交互 TTY 下行为不同，需要充分测试
3. **向后兼容**：已有用户升级 v0.1.0 必须能平滑过渡，不能要求重新设置
4. **启动性能**：解密操作需控制在 1s 内，否则用户体验断崖式下降
